## 3. 真机覆盖矩阵

| 维度 | 必需覆盖 |
|---|---|
| Mac 系统 | 最低支持系统与当期正式系统；新系统截图/录屏行为另验 |
| Mac 架构 | Apple Silicon；Intel 兼容目标须另有实际设备证据 |
| 输入/输出应用 | TextEdit、Notes、Safari、Finder、Mail；另选实际使用的 Office/WPS、代码编辑器、设计工具形成支持矩阵，缺少的软件明确未测 |
| 移动设备 | 最低支持系统 iPhone + 当期系统 iPhone；至少一台支持目标多任务方式的 iPad |
| 同步账号 | 两设备同账号；两账号共享；测试容器与生产配置分别标记 |
| AI | 模型可用与不可用设备/地区条件，权限拒绝与关闭 |
| MCP | 至少两个真实客户端，其中一个通用自定义 MCP 客户端；协议版本和传输记录 |
| 网络/存储 | 离线、抖动、iCloud 配额、附件部分下载、低本地空间 |

不能因为没有设备就将该维度记通过；可先完成独立工作，再保留明确待验收项。用户真实信息不得作为必要测试夹具。

## 4. 记录模板与完成定义

实施时每条填写：`Q 编号 / 适用平台 / 构建 commit / OS 与设备 / 层级 / 实际结果 / 证据路径或摘要 / 状态 / 未覆盖边界`。状态仅使用未执行、通过、失败、受阻、不适用；不适用必须给平台/范围理由，不能用于隐藏失败。

“任务完成”必须同时有实现、所关联用例通过和差距说明。“macOS 完整”必须满足实施计划 G-MAC；“全平台完整”必须满足 G-ALL。编号完整、链接正确和文档结构检查只证明这套规格可追踪。
