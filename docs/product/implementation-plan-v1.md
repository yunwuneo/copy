# Copy 完整产品实施计划 v1

日期：2026-10-15。依据：[完整功能规格](product-spec-v1.md)；测试索引：[对标与验收](acceptance-and-traceability.md)。原文编制时任务均未开始；现已进入实施，实时状态以 [实施记录](../implementation-progress.md) 为准。

## 1. 唯一交付顺序

**macOS 完整产品 → macOS 完整验收 → iOS/iPadOS 完整产品 → 跨平台整体验收。**

不设置 MVP、日用版、精简版或基础版发布。以下任务是实现依赖和检查点，不是给用户分档的产品版本。内部验证构建只用于发现问题，不能作为完整版替代交付。

Mac 必须先完成全部适用功能，包含 OCR、批量/队列、iCloud、共享、系统自动化、写作工具、智能推荐及 MCP。Mac 阶段使用两台 Mac、两个测试 Apple Account 验证同步/共享；iPhone 仅作为扫描的系统外设可以参与。Copy 移动 App 和扩展在 T20 通过后开始。

## 2. 开始实施前的固定动作

1. 阅读仓库 AGENTS、README、本规格、调研和验收文档，检查当前代码与未提交变更。
2. 生成现状差距表：需求编号、现有实现、缺失、对应任务、已有证据。当前只有文档，不能填“功能已完成”。
3. 查看已安装 Xcode/SDK、签名能力、可用设备和空间；优先复用，不自动安装多个模拟器或新建环境。
4. 把产品假设与技术可行性分开：先验证窗口/焦点/权限、文件类型、iCloud、屏幕保护及键盘约束，再固定关键接口。
5. 建立简短实施记录 `docs/implementation-progress.md`（实施开始时创建）：任务状态、变更、证据路径、实际差距和下一项。规格结构通过不算功能通过。

## 3. 模块边界与仓库结构

建议一个仓库、一个共享核心；不为 Mac 和移动分别复制整套数据模型。下列是规格阶段建议的位置；实际实施使用根 SwiftPM 管理 Packages 与 Apps，详见实施记录。

```text
Apps/CopyMac/                 菜单栏、快捷面板、资料库、系统权限与粘贴
Apps/CopyMobile/              后续 iPhone/iPad 主应用
Extensions/                  后续 Share、Action、Keyboard、Widget
Packages/CopyCore/            领域对象、规则、操作状态及协议
Packages/CopyStorage/         SQLite、附件、迁移、索引、接收箱
Packages/CopySync/            CloudKit 适配、冲突、共享
Packages/CopyAutomation/      App Intents、MCP 与审批
Tests/                       单元、集成、小型合成样本与故障注入
docs/                        规格、决策与验收摘要
work/                        受控构建/临时结果；不纳入 Git
```

Core 不依赖 AppKit/UIKit、CloudKit 或 UI；平台入口调用应用服务，再访问存储。核心接口至少包括 CaptureService、ItemRepository、SearchService、AssetStore、PasteService、CollectionService、RetentionService、SyncCoordinator、AccessPolicy、OperationJournal。跨进程事务和权限在服务/存储层执行，不依赖页面状态。

初选原生 SQLite + FTS 与文件内容存储，CloudKit 显式同步；T03 要验证中文检索策略，不能认为默认分词自动满足中文。第三方封装只有在能明确降低实现风险时引入，记录许可证、大小、维护状态和锁定版本。AI 不引入第三方模型包；MCP 实现根据届时官方协议选最小必要依赖。

## 6. 交付门槛

### G-MAC：macOS 完整产品

- T00–T20 全部实现并有结果；R01–R18、R22–R23 的 Mac 部分及 R24 数据保护契约通过。
- F 对照表所有 Mac 适用行均有证据；移动专属行明确标“待移动阶段”，不能误算缺陷或完成。
- 两台真实 Mac 验证个人同步；两个独立测试账号验证共享。直接粘贴在真实目标应用验证，不以模拟器或 mocked paste service 代替。
- 系统权限拒绝/撤销、空磁盘余量、索引损坏、附件失败、断网、账号切换、操作结果不确定均测试。
- AI 可用设备与不可用路径分别测试；MCP 使用真实本机客户端做授权/撤销/写入验证。
- 完整导出/恢复、版本迁移、签名/公证安装、24 小时运行通过；无未解决的数据丢失、越权、泄露或重复外部写入缺陷。
- 未关闭的功能等价差距明确列出；不能把“可用但缺功能”当作 G-MAC 通过。系统天然限制按规格支持矩阵判断，不要求不可能的平台能力。

G-MAC 是产品完整验收，不要求先公开商店发布。无签名/设备时应记录受阻门槛，继续完成不依赖该条件的 Mac 工作，不编造通过也不自行进入移动实施。

### G-ALL：macOS + iOS/iPadOS 完整产品

- T21–T29 完成；R19–R21 和共用模块的移动部分全部通过。
- Mac、iPhone、iPad 三端真实内容、删除、编辑、收藏、共享行为一致；明确移动采集/键盘系统限制。
- 所有扩展在受支持系统与目标宿主上测试，含 Full Access 拒绝、安全输入、系统终止与内存压力。
- 同步生产环境配置、签名/构建/升级和真实安装有证据；测试数据库成功不等于生产容器成功。
- 全部 F 行有“等价通过/平台限制/商业范围外/仍有差距”的最终结论；存在仍有差距的核心功能不得称为完整替代。

### 缺陷分级

P0：越权、敏感数据泄露、不可恢复数据丢失、重复危险写入；任何交付门槛禁止通过。P1：对标核心行为缺失、持续崩溃、错误粘贴到目标、同步删除复活；必须修复。P2：有明确绕行的非核心交互或性能问题；只有不破坏规格验收目标时才可记录为已知问题。P3：纯视觉细节。

## 7. 验证与证据管理

测试分为 L1 领域规则/单元、L2 本地存储/进程集成、L3 真机系统/目标应用、L4 跨设备/账号/真实客户端、L5 签名发布/耐久。证据必须注明层级，L1/L2 不能替代 L3–L5。

每项验收记录：需求和 Q 编号、构建 commit、设备/OS、前置设置、合成输入、实际操作、观察结果、通过/失败、日志或截图路径、未覆盖边界。测试脚本与小样本入仓库；大日志/截图/安装包不提交 Git。只保留每个门槛最新有效证据和必要的失败证据，汇总表保留哈希与路径。

禁止为了验证而读取用户真实剪贴板、共享真实业务集合或自动发消息。实际桌面交互与系统授权按用户既有授权范围执行；没有授权时先完成可独立进行的代码和合成测试，再说明具体缺少的实测授权。

## 8. 资源与风险处置

| 风险 | 提前处理 | 受影响任务与停止条件 |
|---|---|---|
| 屏幕保护无法覆盖新捕获链路 | 先探针、再确定支持矩阵；提供真实遮挡模式 | T01/T18；不得宣称全防录屏 |
| 富文本/设计对象不可还原 | 保存多表示，建立源/目标矩阵，明确降级 | T02/T07/T09；不能静默扁平化 |
| CloudKit 账号/签名/容器不可用 | 确认权限；本地协议先测试，真实集成保留待验收 | T01/T13/T14/T26 |
| 同步删除和冲突 | 墓碑、generation、版本对账及故障注入 | T11/T13；出现复活/丢数据阻止 G-MAC |
| iOS 扩展系统终止 | 接收箱短事务、轻量索引、缩略图预算 | T22/T23；不能用主应用成功代替扩展测试 |
| 智能推荐不支持目标设备/地区 | 可用性检查、普通搜索降级，不引入未授权云模型 | T16；支持条件下的功能仍须实测 |
| Paste 无通用导出格式 | 先小样本格式研究，只提供确实可读的导入器 | T12；无可靠来源则保留专用迁移差距 |
| 硬盘不足 | 单一构建目录、逐平台构建、流式生成、设上限 | 所有任务；不自动安装 SDK/模拟器或复制大历史 |
| API/竞品变化 | 锁定验收快照，变更进入规格修订 | 不临时追逐新功能导致已确定范围失焦 |
